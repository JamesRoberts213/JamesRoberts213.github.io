Deterministic UI & Low-Latency Refresh

Because driving a $240 \times 320$ 16-bit RGB565 display over SPI on an 8-bit ATmega328P can introduce visible screen tearing if the entire frame is cleared every loop, the firmware uses dirty-rectangle partial redraws.

  • Selective Region Updates: Only the central yardage digits and active target bounding box are overwritten when new NMEA `$GPGGA` sentences arrive at $1\text{ Hz}$.
  • Hardware Debounced State Machine: Tactile switches trigger state transitions with a $50\text{ ms}$ non-blocking `millis()` lockout timer—preventing missed inputs without halting serial GPS parsing.
  • High-Contrast Daylight Palette: Pure black (`0x0000`) background paired with high-luminance white, cyan, and amber typography ensures readability in direct outdoor sunlight.

Engineering Deep-Dive: Firmware, PCB & CAD

Explore the three core technical pillars developed to bring the device from concept to working prototype.

Written in Embedded C++ (VS Code + PlatformIO / Arduino toolchain). To operate reliably within the ATmega328P's $2\text{ KB}$ SRAM limit, course green coordinates are stored in non-volatile Flash (`PROGMEM`), and great-circle yardage is computed via the spherical Haversine formula:

$$d = 2R \arcsin\left(\sqrt{\sin^2\left(\frac{\Delta\phi}{2}\right) + \cos(\phi_1)\cos(\phi_2)\sin^2\left(\frac{\Delta\lambda}{2}\right)}\right)$$
rangefinder_core.cpp — Haversine & PROGMEM Lookup C++ / AVR 
#include <avr/pgmspace.h>
#include <math.h>

// Store green coordinates (Front, Center, Back) in Flash to preserve 2KB SRAM
struct GreenCoords { float lat; float lon; };
const GreenCoords courseData[18][3] PROGMEM = {
    {{54.01042f, -2.78512f}, {54.01055f, -2.78501f}, {54.01068f, -2.78489f}},
    // ... remaining 17 holes indexed in Flash
};

// Compute real-time yardage using spherical Haversine formulation
uint16_t calculateYards(float lat1, float lon1, uint8_t hole, uint8_t pinPos) {
    GreenCoords target;
    memcpy_P(&target, &courseData[hole][pinPos], sizeof(GreenCoords));

    const float R_YARDS = 6967410.0f; // Earth mean radius in yards
    float dLat = radians(target.lat - lat1);
    float dLon = radians(target.lon - lon1);

    float a = sin(dLat * 0.5f) * sin(dLat * 0.5f) +
              cos(radians(lat1)) * cos(radians(target.lat)) *
              sin(dLon * 0.5f) * sin(dLon * 0.5f);

    float c = 2.0f * atan2(sqrt(a), sqrt(1.0f - a));
    return (uint16_t)round(R_YARDS * c);
}

Circuit Architecture & Layout Strategy

  • Schematic Capture & Routing: Transitioned the point-to-point perfboard prototype into a unified 2-layer PCB layout (KiCad / EasyEDA) with dedicated ground planes to minimize high-frequency SPI noise coupling into the GNSS RF front-end.
  • Mixed-Voltage Level Shifting: Integrated resistive voltage dividers and 3.3V regulation to safely interface the 5V ATmega328P logic outputs with the 3.3V ST7789V TFT controller.
  • Power Distribution & BMS: Routed wide power traces ($20\text{ mil}$) for the TP4056 Li-Ion charger, physical slide power switch, and decoupling capacitors ($100\text{ nF}$ ceramic + $10\text{ }\mu\text{F}$ bulk) adjacent to IC power pins.
  • Hardware Debouncing: Added RC filtering and pull-up networks on the tactile user push-buttons for clean state transitions on the course.

Key Engineering Takeaways

SRAM Optimization on ATmega328P

Constrained dynamic memory ($2\text{ KB}$ SRAM) required storing course coordinate lookup tables in `PROGMEM` flash memory and avoiding dynamic `String` heap fragmentation during SPI screen refreshes.

3.3V / 5V Logic Level Shifting

Protected the 3.3V ST7789V display controller from 5V Arduino logic levels using resistive voltage dividers on the SPI clock and data lines to ensure long-term signal integrity.

Design for Assembly (DFA) in FDM

Learned how wall thickness around bosses affects melt flow when installing heat-set brass inserts at $210^\circ\text{C}$, preventing exterior surface bulging on thin PLA walls.

NMEA Parsing & Cold-Start Filtering

Implemented dilution-of-precision (HDOP) filtering in firmware to prevent erratic yardage jumps while the GNSS receiver acquires initial satellite lock.

Partial Redraw SPI Frame Pacing

Eliminated visible display flicker by updating only modified numeric bounding boxes over hardware SPI rather than clearing the full $240 \times 320$ pixel buffer each cycle.

GNSS RF Ground-Plane Isolation

Maintained a copper keep-out zone beneath the ceramic GNSS patch antenna during PCB layout to prevent ground-plane detuning and preserve satellite acquisition sensitivity.
